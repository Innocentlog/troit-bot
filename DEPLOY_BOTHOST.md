# Деплой бота на BotHost (bothost.ru)

BotHost — это PaaS: платформа сама собирает Docker-образ, запускает контейнер,
перезапускает при падении и даёт персистентное хранилище `/app/data`.
Root-доступа нет, systemd не нужен.

## Шаг 1. Регистрация и тариф

1. Зарегистрируйтесь на https://bothost.ru
2. Активируйте тариф **Basic — 99 ₽/мес** (нужен для: персистентного хранилища,
   переменных окружения, выбора локации, загрузки из архива).
3. В профиле → «Интерфейс» → включите **«Загрузка бота из архива»**
   (если не хотите публиковать код в публичный git).

## Шаг 2. Перевыпустить токен бота

Старый токен был опубликован в чате и записан в config.py — **обязательно revoke**:

1. Откройте @BotFather в Telegram
2. `/mybots` → выберите `@TroizaAdmin_bot` → API Token → **Revoke current token**
3. Новый токен **нигде не публикуйте** — он пойдёт только в панель BotHost

## Шаг 3. Подготовить архив бота

В папке `bot/` лежат нужные файлы:

```
main.py            # точка входа (запускает bot.py)
bot.py             # логика бота
config.py          # читает переменные окружения, секретов не содержит
requirements.txt   # aiogram, httpx, aiohttp-socks
bothost.json       # подсказка BotHost: main.py, python 3.11
ENV.md             # список переменных окружения
```

Исключить из архива: `venv/`, `bot.db`, `log.txt`, `config.vps.example.py`,
`config.example.py`, `data/`.

PowerShell (из папки `site troizky hram new`):

```powershell
cd bot
Compress-Archive -Path main.py, bot.py, config.py, requirements.txt, bothost.json -DestinationPath ..\bot-bothost.zip -Force
cd ..
```

## Шаг 4. Создать бота в панели BotHost

1. Дашборд → **«Создать бота»** (create-bot.php)
2. Название: любое, например `troit-bot`
3. Платформа: **Telegram**
4. Библиотека: **aiogram 3.x**
5. **Bot Token**: вставьте новый токен от @BotFather
6. Способ загрузки: **«Загрузить из архива»** → выберите `bot-bothost.zip`
   (или укажите Git URL приватного репозитория, если настроили доступ)
7. Дополнительные настройки:
   - Главный файл: `main.py`
   - Ветка: `main`
8. Создать → дождаться окончания сборки (видно в «Логи сборки»)

## Шаг 5. Задать переменные окружения

Настройки бота → **«Переменные окружения»** (доступно на платном тарифе).
Добавьте по списку из `ENV.md`:

```
ADMIN_IDS      = 397809686,126426602
CHANNEL_ID     = @troizadm
SITE_URL       = https://dmtroizahram.ru
BOT_API_KEY    = <тот же ключ, что в domains/config.php на Джино>
API_BASE_URL   = (пусто)
PROXY_URL      = (пусто)
```

`BOT_TOKEN` платформа подставляет сама из формы создания бота (алиасы:
`API_TOKEN`, `TELEGRAM_BOT_TOKEN`).

После сохранения переменных → **перезапустить бота** (Restart/Redeploy).

## Шаг 6. Проверка

В панели: «Логи работы» — должны появиться строки:

```
INFO troit-bot Бот запущен
```

В Telegram:

1. `/start` в личку боту — должен ответить приветствием (если ваш ID в ADMIN_IDS)
2. `/schedule` — мастер ввода расписания
3. `/notes` — список записок с сайта (нужен рабочий `BOT_API_KEY`)
4. `/log` — журнал публикаций
5. `/gallery` — подсказка

Проверка записи на сайт: `/schedule` → ввести одну службу → «Публикация сейчас»
→ открыть https://dmtroizahram.ru/#schedule и убедиться, что служба появилась.

Проверка записок: отправить записку через форму на сайте → через ~60 секунд
бот должен прислать уведомление в личку админу.

## Шаг 7. Локация и «Зарубежный IP»

На платном тарифе в настройках бота можно выбрать локацию. Если Telegram API
внезапно перестанет отвечать или начнутся 429 — включите в профиле опцию
**«Зарубежный IP для API»** и перезапустите бота.

## Обновление бота

- Из архива: загрузить новый `bot-bothost.zip` через дашборд (данные в `/app/data` сохраняются)
- Из Git: `git push` → автообновление по webhook (платный тариф)

## Откат на VPS

Если BotHost не подойдёт, в репозитории остаётся рабочий вариант VPS:
см. `config.vps.example.py` и старый раздел DEPLOY.md про systemd.
